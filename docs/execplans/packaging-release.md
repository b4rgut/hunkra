# Fedora distribution and release boundaries

HNK-014 preserves one product version managed only by release-plz. Local packaging never bumps versions, creates tags, publishes or installs into the owner's system. Fedora x86_64 is the tested target; a distribution built on another system is not silently labeled compatible.

`bootstrap --packaging` verifies Fedora RPM signatures before extracting missing rpmbuild tools into `.tools/rpm-build`. The host's rpm-build-libs must be available. Packaging selects complete RPM configuration at startup through RPM_CONFIGDIR when using extracted tools. Rebinding only `_rpmconfigdir` left automatic ELF dependencies empty during spec parsing; the actual package assertion caught this. No automatic dependency check was disabled.

`package-rpm /ABS/NEW/OUTPUT` builds the locked optimized GUI binary, checks its display-independent `--version` against the workspace, collects 609 exact Linux normal/build dependency declarations and available notice texts, and assembles a real RPM in a private buildroot. The unmodified MPL-2.0 option-ext source is included. Product licensing remains LicenseRef-Hunkra-Unselected. Native libraries remain supplied by Fedora packages. Output must be new or empty; caller files are never overwritten.

`check-package /ABS/FILE.rpm /ABS/REPORT.json [--native]` repeats real assembly with the same input binary/payload/source epoch, compares complete RPM SHA-256, verifies every extracted file mode/digest and notice, resolves declared dependencies through installed Fedora providers, checks launcher/version without display, and optionally runs all native fixture groups from the extracted binary. The existing77 scenarios are joined by the new bounded native editor-layout case (78 total); prior77-case RPM reports are not retroactively claimed to cover it. Input and stripped packaged binary hashes are recorded separately. Equal RPM bytes for fixed input are not a claim that independent full Rust builds across hosts are identical.

Dependency notices and their manifest are `%license` payload under `/usr/share/licenses/hunkra`; build identity is required payload under `/usr/share/hunkra`. Optional README is `%doc`. An actual clean Fedora installation initially revealed that the base container excludes documentation: launcher/version worked while doc-marked identity/notices were absent. That layout was corrected; the final installation check explicitly uses `tsflags=nodocs` and verifies mandatory license/source/identity files.

`check-package-install /ABS/FILE.rpm /ABS/REPORT.json` requires Podman. It uses rootless containers with project-private storage under ignored target/, a verified pinned official Fedora 44 manifest from packaging/fedora-image.txt, one read-only artifact mount and a uniquely named disposable container. It runs real DNF installation, RPM verification and headless version launch; it does not access the owner's RPM database, container storage, home, Git settings or display. The base-image cache remains reusable. Timeout cleanup removes only this owned test container.

The prepared artifact workflow uses the same Fedora manifest, shared commands and read-only repository permissions. `artifact-check.py` rejects tag/workspace/internal-pin/lock/HEAD mismatches. It is tested after real release-plz update and a simulated local squash acceptance in disposable mini-workspaces, including core-only/locales-only changes. These fixture tags never enter the product repository. Actual optimized RPM assembly and native installation are checked separately.

GitHub release PR creation/acceptance, token scopes, environment protection, tag-trigger behavior and artifact job execution require owner-controlled external configuration. No remote chain was executed, and the YAML is not presented as proof of a completed release. Publication is explicitly excluded from this run. Required external settings are described in docs/workflow.md. Full MVP acceptance remains separate HNK-015.
