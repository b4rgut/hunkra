# gix-first — проверено gix 0.88.0

Production core does not start Git CLI subprocesses. Configured clean filters can launch their normal external commands through gix. Tests and demo generator use independent Git 2.55.0 only in disposable repos. User errors remain errors; no blanket fallback or second executor retry exists.

Primary API source: https://docs.rs/gix/0.88.0/gix/struct.Repository.html ; downloaded crates.io source gix 0.88.0 and its official gix-* packages. Reproduction: `scripts/dev check` (crates/hunkra-core/tests/repository.rs).

Viewing retains source bytes; presentation strips newline for labels only and records CRLF/LF/EOF, with ∅ marker. Unsupported encodings have no lossy-edit path. Text clipping/scroll UX and performance measurements are separate UI tasks, not evidence of Git support. Credentials/signing and mutation hooks are not certified by index tests. Executable post-index-change is detected and refused, rather than omitted. Unsupported variants do not justify replacing the working gix path with CLI.

Write sources verified 2026-10-05: [gix index State](https://docs.rs/gix/0.88.0/gix/index/struct.State.html), [gix-lock 25 File](https://docs.rs/gix-lock/25.0.0/gix_lock/struct.File.html), local registry source at the exact Cargo.lock revisions. [Gitoxide issue 2421](https://github.com/GitoxideLabs/gitoxide/issues/2421) explains stale TREE; our write explicitly calls remove_tree and an independent Git commit test proves the selected content reaches its tree. [Git core.fileMode](https://git-scm.com/docs/git-config#Documentation/git-config.txt-corefileMode) is honored through gix filesystem options and Mode change primitives, preserving an existing executable mode when filesystem mode is ignored.

Reproduction: scripts/dev check (26 core integration tests + 6 app tests), scripts/dev check-ui/build-ui, scripts/dev smoke /ABS/REPORT.json. Native smoke constructs and deletes its own demos; exact intermediate index versions and final Git oracle are in docs/validation/index-selection.json. Tests use an isolated home/config, local identity/hooks and no owner Git environment.

Guarantee boundary: index.lock coordinates cooperating Git writers. Worktree files have no universal editor lock; their exact bytes are checked immediately before atomic index replacement, but noncooperating external writes between that check and rename cannot be categorically excluded. A very late refusal can leave an unreferenced blob; index/worktree stay unchanged. Normal close waits for writing; forced kill is not a safe cancellation API.

State::write_to 0.56.0 serializes TREE/sdir/EOIE but omits REUC conflict-undo data. An actual resolved-merge fixture proves we refuse before changing index/REUC. Optional performance caches are not preserved by this writer; extending extension round-trips is HNK-017.
