# gix-first — проверено gix 0.88.0

Production reads/ref creation/index/ordinary Commit use gix. Full worktree switch/merge/rebase lifecycle explicitly selects Git CLI before writing because their complete application coordinators are absent from the audited gix APIs. Configured clean filters can launch their normal external commands through gix. Tests and demo generator use independent Git 2.55.0 only in disposable repos. User errors remain errors; no blanket fallback or second executor retry exists.

Primary API source: https://docs.rs/gix/0.88.0/gix/struct.Repository.html ; downloaded crates.io source gix 0.88.0 and its official gix-* packages. Reproduction: `scripts/dev check` (crates/hunkra-core/tests/repository.rs).

Viewing retains source bytes; presentation strips newline for labels only and records CRLF/LF/EOF, with ∅ marker. Unsupported encodings have no lossy-edit path. Text clipping/scroll UX and performance measurements are separate UI tasks, not evidence of Git support. Credentials/signing and mutation hooks are not certified by index tests. Executable post-index-change is detected and refused, rather than omitted. Unsupported variants do not justify replacing the working gix path with CLI.

Guarantee boundary: index.lock coordinates cooperating Git writers. Worktree files have no universal editor lock; their exact bytes are checked immediately before atomic index replacement, but noncooperating external writes between that check and rename cannot be categorically excluded. A very late refusal can leave an unreferenced blob; index/worktree stay unchanged. Normal close waits for writing; forced kill is not a safe cancellation API.

State::write_to 0.56.0 serializes TREE/sdir/EOIE but omits REUC conflict-undo data; REUC fields are private. The adapter now locates extensions in validated v2/v3/v4 input (official EOIE decoder, otherwise a bounded format walk), retains REUC bytes, and combines official State::write_to + hash::io::Write + extension::Iter with that payload before checksum. Tests cover both object formats, three index versions and EOIE on/off; Git ls-files --resolve-undo stays equal and checkout -m reopens the real conflict even after updating its own resolved path. TREE/UNTR/FSMN/EOIE/IEOT performance caches are invalidated; unknown extensions are refused before writing any object. Primary format: [Git index format](https://git-scm.com/docs/gitformat-index). No production Git subprocess is involved.

EOF policy is exact bytes: independent halves work when the retained old line ends in LF/CRLF. Combining an unterminated old EOF with a new line would require an unselected separator or silent concatenation; that half is explicitly refused, preserving the UI selection. Choosing both sides writes the exact requested replacement. Stage/unstage matrix and unchanged worktree are independently verified with Git. A retryable error retains the immutable diff/selection; successful or stale writes invalidate it, and a later changed source clears it. Native lock refusal verifies the owned error remains visible after refresh.
