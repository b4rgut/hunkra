# HNK-024 — workspace UI

Scope: the owner's 2026-10-06 screenshot request. Owned GPUI layout follows the reference's compact title row, sidebar-aligned tabs, full-height comparison and sidebar commit editor. The default shared palette is GitHub Dark. Project opening, recent projects, init and clone are in the application menu. Minimize, Maximize/Restore and Close controls are in the title row with translated tooltips and in the application menu. Maximize/Restore follows the actual window state; Close delegates to the existing dirty Result/active writer guard. The title row remains available above open menus. Preferences are a separate overlay opened with Settings or Ctrl+, and closed with Escape, the close button or an outside click.

Language defaults to `System`. Linux message preferences use the first nonempty LC_ALL / LC_MESSAGES / LANG category, then supported LANGUAGE preferences where the category is not C/POSIX. Russian resolves to ru-dev, English and unsupported languages to en. Explicit En/Ru/RuDev settings from older versions remain explicit; recent projects remain intact. Preferences keep the same diff, selection, inputs, revisions and repository generations. The previous input focus is restored on closing. Diff details and hints are off by default and can be enabled in preferences or the comparison toolbar; mode-only changes still show their metadata.

The registered GPUI acceptance uses real mouse/keyboard dispatch on the isolated TestPlatform. At 1280×820 the sidebar is 320 px, the commit editor is contained in it, and the comparison is over 650 px tall. It clicks every language option and diff-details checkbox, checks System versus explicit preference, Escape and Ctrl+, blocks Ctrl+Enter behind the settings overlay, and checks unchanged private Git bytes. Clicking Close above the open preferences while a writer is active closes preferences and sets the deferred-close flag without removing the window. Headless tests check locale precedence and legacy/partial settings without changing environment variables.

The initial native UX run exposed a focus regression: closing preferences left focus on the host, so Tab did not move from the filter to the commit message. Capturing/restoring the previous focus and stopping the settings button's mouse-down propagation corrected both registered click and native keyboard paths. Checks were retained.

Validation uses the normal project wrappers: check, check-ui, check-editor, build-ui and all nine finite native smoke groups on the optimized release binary. The added window-control scenario observes compositor acknowledgements of maximize and restore and invokes minimize. GPUI 0.2.2 TestPlatform has unimplemented minimize/zoom methods, so those commands are tested on the actual Wayland platform; the close-button click/guard is tested through registered TestPlatform dispatch. Exact source and binary identities, totals and reports are recorded in workspace-ui-source.json. The native UX phases actually open preferences, switch en/ru/ru-dev and toggle details while preserving snapshots and drafts. Independent Git/byte oracles cover the temporary repositories; smoke settings are isolated and never persisted to owner configuration.

This is functional native Wayland validation and registered layout/event acceptance. Pixel comparison with the screenshot, physical mouse/keyboard/IME, the minimized appearance, X11/GPU acceptance and an updated installed RPM are not established by these checks. The earlier certified RPM remains evidence for its earlier source. HNK-014/015 retain their prior status and limits; no remote release action was requested.
